# GR00T-N1.6-bridge VLA Error Analysis

## Overview

This document analyzes the prediction error between GR00T-N1.6-bridge's VLA outputs and the oracle (expert) actions from BridgeData-V2. The analysis covers 1,000 episodes (36,027 timesteps) from the same dataset used to finetune the model.

**Purpose**: Inform the design of the Cerebellar Correction Module (Phase 2), which learns `delta_a = action_expert - action_vla` as a state-dependent correction.

---

## 1. Extraction Pipeline

### Data Sources
- **Expert actions**: From BridgeData-V2 parquet files, column `action` (7-dim numpy arrays)
- **VLA actions**: Generated by running frozen GR00T-N1.6-bridge inference on each timestep
- **Extraction script**: `cerebellar_correction/data/extract_all.py`

### Action Dimensions (in order)
```
[x, y, z, roll, pitch, yaw, gripper]  # 7 dimensions
```
- Position (x,y,z): End-effector Cartesian deltas
- Orientation (roll, pitch, yaw): Euler angle deltas
- Gripper: Binary open(1)/close(0)

### GR00T Processing Pipeline (for WidowX/BridgeData)
- **Normalization**: Mean/std for `[x, y, z, roll, pitch, yaw]`, min/max for `gripper`
- **Action representation**: ABSOLUTE (no relative conversion despite `use_relative_action: True` in processor; all `action_configs` specify `rep: ABSOLUTE`)
- **Action horizon**: 8-step chunks (`delta_indices: [0,1,...,7]`)
- **Diffusion**: Flow matching with 4 inference timesteps, 32-layer DiT
- **State dropout**: `state_dropout_prob=0.8` — **always active, even at inference** (not gated by `self.training`). 80% of the time, proprioceptive state is replaced with a learned mask token.
- **Attention dropout**: `attn_dropout=0.2` (also in config, may be active at inference)
- **Sin/cos state encoding**: Applied to state inputs

### Key Bug Fixes Applied Before This Analysis
1. **Variable backbone sequence length**: Eagle backbone outputs 103-164 tokens (not fixed 108). Fixed with pad/truncate to MAX_TOKENS=128.
2. **Action dimension ordering**: `sorted(action_dict.keys())` produced `[gripper, pitch, roll, x, y, yaw, z]` instead of correct `[x, y, z, roll, pitch, yaw, gripper]`. Fixed with explicit `ACTION_KEYS` constant.
3. **torch.save fp16 bloat**: Switched intent tokens to `.npz` format (3-6x storage reduction).

| Dim | Pearson r | R^2 | VLA_std/Expert_std | MAE/Expert_std | MSE_vla/MSE_zero |
|---------|-----------|---------|---------------------|-----------------|-------------------|
| x | 0.4468 | 0.1767 | 0.5941 | 0.6051 | 0.8230 |
| y | 0.4956 | 0.2331 | 0.6058 | 0.5689 | 0.7666 |
| z | 0.5487 | 0.2883 | 0.6114 | 0.5728 | 0.7117 |
| roll | 0.4010 | 0.1413 | 0.5393 | 0.6062 | 0.8587 |
| pitch | 0.4006 | 0.1052 | 0.5671 | 0.6371 | 0.8674 |
| yaw | 0.4183 | 0.1569 | 0.5526 | 0.5884 | 0.8431 |
| gripper | 0.8338 | 0.6674 | 0.9995 | 0.1676 | 0.1408 |

**Column explanations**:
- **Pearson r**: Correlation between expert and VLA actions (1.0 = perfect)
- **R^2**: Fraction of expert variance explained by VLA (1.0 = perfect)
- **VLA_std/Expert_std**: Ratio of VLA output spread to expert spread (<1 = conservative)
- **MAE/Expert_std**: Mean absolute error normalized by signal variation (lower = better)
- **MSE_vla/MSE_zero**: MSE ratio vs. always-predict-zero baseline (<1 = better than zero)

### Interpretation

1. **Uniform quality across position AND orientation**: R^2 ranges 0.10-0.29 for all continuous dims. The earlier impression that "orientation is 91-96% of error" was misleading — that was raw MSE fraction, driven by orientation dims having 2-5x larger scale. When normalized by signal standard deviation, **all continuous dims are equally poorly predicted** (MAE/Expert_std ~ 0.57-0.64).

2. **Systematic conservative bias**: VLA_std is consistently 54-61% of Expert_std across all dims. The model predicts smaller actions than the expert — a classic "regression to the mean" effect from multi-modal averaging.

3. **Only 17-29% better than predicting zero**: For continuous dims, VLA reduces MSE by only 17-29% compared to a trivial zero-prediction baseline. This is surprisingly poor for a model trained on this exact data.

4. **Gripper is well-predicted**: R^2 = 0.67, binary accuracy = 91.8%.

## 9. Model Configuration Findings

### state_dropout_prob = 0.8 (ALWAYS active at inference)

```python
# gr00t/model/gr00t_n1d6/gr00t_n1d6.py:182-188
if self.state_dropout_prob > 0:  # NOT gated by self.training!
    do_dropout = (
        torch.rand(state_features.shape[0], device=state_features.device)
        < self.state_dropout_prob
    )
    do_dropout = do_dropout[:, None, None].to(dtype=state_features.dtype)
    state_features = state_features * (1 - do_dropout) + self.mask_token * do_dropout
```

**This runs at inference time.** The model was trained with state dropout = 0.8, and the config.json bakes `state_dropout_prob: 0.8` into the checkpoint. There is no `if self.training:` guard. Consequences:
- With batch_size=1, each inference has an 80% chance of seeing no proprioceptive state
- This makes individual predictions stochastic and partially explains the low R^2
- The model was designed to work primarily from vision + language, with state as an optional auxiliary signal
- **Our extraction used batch_size=8**: within each batch, ~80% of samples randomly had state masked. This is consistent with normal GR00T inference.

### Other config details
- `attn_dropout: 0.2` — present in config, likely active at inference if not training-gated
- `num_inference_timesteps: 4` — diffusion denoising steps
- `noise_beta_alpha: 1.5, noise_beta_beta: 1.0` — Beta distribution for noise schedule
- `select_layer: 16` — VLM backbone features extracted from layer 16 of Qwen3-1.7B

### Finetuning script (`examples/SimplerEnv/finetune_bridge.sh`)
```bash
torchrun --nproc_per_node=8 gr00t/experiment/launch_finetune.py \
    --base_model_path nvidia/GR00T-N1.6-3B \
```

## 10. Why Is Per-Step Prediction Quality Low?

Despite being trained on this exact dataset, GR00T-N1.6-bridge explains only 10-29% of per-step action variance (R^2). Several factors explain this:

### 10.1 Stochastic State Dropout (Primary Factor)
With `state_dropout_prob=0.8` active at inference, the model randomly drops proprioception 80% of the time. Without state information, the model must predict actions purely from vision + language, making it harder to produce precise per-step actions. This is by design — the model was trained to be robust to missing state.

### 10.2 Diffusion Sampling Stochasticity
GR00T uses flow matching (a type of diffusion) to generate actions. Each inference produces a different sample from the learned action distribution. For multi-modal tasks (where multiple valid actions exist for the same observation), the model correctly captures the distribution but any single sample may differ significantly from the specific expert action recorded.

### 10.3 Multi-Task Averaging
BridgeData contains ~53K episodes across hundreds of distinct tasks. For common visual scenes (e.g., table with multiple objects), many different task-appropriate actions exist. The model must resolve this ambiguity from the language instruction alone, which may not always perfectly disambiguate.

### 10.4 Chunk Optimization vs. Single-Step Accuracy
The model optimizes 8-step action chunks jointly. The loss function weights the entire trajectory, not individual steps. The model may sacrifice per-step accuracy for better overall trajectory coherence.

### 10.5 Conservative Prediction Bias
The VLA systematically predicts smaller actions (VLA_std = 54-61% of Expert_std). This is a rational strategy under uncertainty — when unsure about action magnitude, predict a smaller action to avoid large errors. However, this means the model consistently under-acts, which the cerebellum can correct.

## 11. Implications for Cerebellar Correction

### 11.1 Error Characteristics Favorable for Correction
- **Zero mean error**: No systematic directional bias — the cerebellum doesn't need to learn a constant offset
- **Conservative bias**: Consistent under-prediction of action magnitudes is a structured, learnable pattern
- **State-dependent errors**: Errors vary with observation context (some timesteps have near-zero error, others have large error) — this gives the forward model's visual/proprio error signals predictive power

### 11.2 max_correction Setting
Based on the error distribution:
- P95 absolute errors: 0.019-0.135 (position-yaw range)
- P99 absolute errors: 0.032-0.210
- **Recommended max_correction**: 0.15 covers P95 for all dims; 0.25 covers P99

### 11.3 Correction Target Distribution
The cerebellum learns `delta_a = expert - vla`. Key properties:
- Zero-mean across all dims (good for initialization)
- Error std is comparable to expert action std (corrections are large relative to signal)
- Corrections are NOT constant — they depend on the current observation state
- The forward model's predicted visual error should correlate with needed corrections

### 11.4 Gripper Handling
Gripper error is binary (0 or 1.0, never intermediate). The cerebellum's continuous correction may not be ideal for this. Options:
- Exclude gripper from correction (pass through VLA's gripper prediction directly)
- Use a separate binary classifier for gripper correction
- Apply sigmoid/threshold after correction
